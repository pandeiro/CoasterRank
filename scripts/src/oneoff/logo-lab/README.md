# logo-lab: Heartline mark pipeline

Regenerates every Heartline mark variant on the workshop page (`app/logo-lab.html`)
from a single traced SVG. One-off tooling — not wired into package.json.

## Files

- `source-sketch.png` — the hand-drawn source design (also copied to `app/public/logos/heartline-source.png`)
- `trace-cut.svg` — potrace trace of the sketch with one surgical edit: a white rectangle at
  `x 774–802, y 504–532` severs the bottom support rail from the ECG pulse lead, so the heart
  can take its own fill without dragging the lattice with it. 12 connected components.
- `compose.mjs` — builds all variant SVGs into `app/public/logos/`
- `mini-source.png` — B/W capture of the winning toggle config (hill + heart + loop);
  the mini mark thickness ladder (heartline-mini-0..3) is generated by morphology
  (Dilate thins / Erode thickens at 2x) + retrace, keeping only levels with exactly
  3 components; colorized by position (leftmost = hill, middle = heart, rightmost = loop)
- `compact2-mark.mjs` — parametric v2 compact mark: hand-drawn asymmetric lift hill
  (gradual straighter lift, steep curved drop) with the heart in front. Real stroked paths,
  so stroke weight is a knob. The hill's hidden stretches behind the heart are computed
  against a guard model (two lobe circles + two bottom-edge segments, expanded by the
  stroke) and exactly trimmed via de Casteljau splits — transparent-background-safe.
  compose.mjs copies this module to `app/public/logos/compact2-mark.mjs`, where the
  workshop page (`app/logo-lab.html`) imports it for the live builder.

## Rebuilding the trace from scratch (macOS)

```bash
magick source-sketch.png -fill white -draw "rectangle 774,504 802,532" cut.png
magick cut.png -compress none /tmp/trace.pbm
potrace -b svg --turdsize 5 --alphamax 1.2 /tmp/trace.pbm -o trace-cut.svg
node compose.mjs
```

## Component index map (compose.mjs)

0 hill · 1 support line · 2 left lattice · 3 hill2 · 4 track · 5 loop ·
6 heart+pulse · 7 right rails+lattice · 8 tail · 9–11 baseline ticks

Path data is in potrace 0.1pt units over a 14360×6020 canvas, y-up (the emitted group
transform `translate(0,602) scale(0.1,-0.1)` flips it). Any custom transform math must work
in path units: `x_svg = tx + s·u`, `y_svg = ty − s·v` with `v = (602 − y_pt)·10`.
